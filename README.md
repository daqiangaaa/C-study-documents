### 为什么这些可能对你有用

大部分题解仓库回答「这题怎么做」。这个仓库更多在回答另外三个问题：

- **这个错为什么编译器不骂我？** —— 比如 `if` 写成 `while` 造成死循环，`-Wall -Wextra` **一个字都不警告**，程序 3 秒打出 276 万行。
- **为什么样例全过、一交就 WA？** —— 比如两个 bug 互相抵消：gcd 那题 40% 的数据是错的、芝士面包 72% 是错的，而样例**恰好全对**。
- **我怎么分清「感觉难」和「真的难」？** —— 比如三维数组那题我以为自己根本写不了，实际 8 行；幻方题我「甚至没有做它的欲望」，实际是 NOIp Day1 的第一题。

## 关于这份仓库的说明

**代码是我自己写的。**

每一道题的实现、每一条报错，都是我亲手敲、亲手撞出来的。那 24 份错题本就是铁证 —— 它们就是我当时提交的原始代码，难看，但真实。

**但文档不全是。**

仓库里的 `*.md` 专题笔记、错题本的整理表格、以及你现在看的这份 README，是我和 **AI 助教**一起做的：我把每次的编译输出粘过去，它帮我翻译成人话；我把每道题的思路讲一遍，它帮我指出哪里绕住了；我随口说一句「这题我又没 AC」，它帮我把散落的教训归成一个体系。

我写明这一点，是因为：

- 这些笔记里的每一个坑**都是真的**，都能在提交记录或当时的编译输出里找到；
- 但把它们写成这么整齐的样子，确实不全是我一个人的功劳。

所以，如果你也在学：

- **`solutions/` 和 `_错题本/` 是原味的**，可以放心看；
- 那些「怎么想」的专题笔记，更像我的**读书笔记** —— 有参考价值，但不必当成教材。

## 编译方式

**Code::Blocks 25.03**（自带 MinGW，gcc 14.2.0）。编译器选项：

```
-finput-charset=UTF-8 -fexec-charset=GBK -Wall -Werror -O2
```

⚠️ **`-O2` 不能省**：`-Wall` 单独开着**抓不到**「变量没初始化」，加上 `-O2` 才会报
`warning: 'cnt' may be used uninitialized [-Wmaybe-uninitialized]`。

⚠️ **`-Werror` 把警告当错误**：因为 Code::Blocks 把警告显示成蓝色，而我一开始总把它当"没报错"忽略掉，
所以干脆让警告直接把编译拦住 —— 红色、且编不出 exe。（[`警告翻译表.md`](警告翻译表.md) 第 6 节有取舍说明）

或者命令行直接编：

```bat
"C:\CodeBlocks\MinGW\bin\gcc.exe" -Wall -Werror -O2 某个文件.c -o 输出.exe
```

⚠️ **源码路径不要用中文。** MinGW 的链接器处理中文路径会直接失败：
`ld.exe: cannot open output file E:\????\_t.exe: No such file or directory`

## 一直在用的几句话

> **`\n` 是这一行的句号，写在行尾。**

> **信息后面还要用就存数组，用完就扔就不存。**

> **scanf 认死理，printf 不挑食。**（`double` 的 scanf 要 `%lf`，printf 用 `%f` 就行）

> **`scanf` 的返回值有三种：`1` / `EOF` / `0`。** 读到 EOF 的循环一律写 `== 1`；`!= EOF` 挡不住"格式对不上"（返回 `0`），那就是死循环。

还有一条专治死循环：**循环体里必须有东西能让「条件看的那个变量」变假。**
写循环先答两问 —— ① 条件看的是哪个变量？② 循环体里改的是**那个变量**吗？
答不上第二个就是死循环，而**编译器一个字都不会警告**（只判断一次要用 `if`，
只有「反复做同一件事」才用 `while`）。已经栽过**四次**，四张不同的脸见 [`易错点总表.md` ⑦](易错点总表.md)。

另外几条，都是被咬出来的：

- **声明的那一刻就把初值写上** —— `int cnt = 0;` 当一个整体敲，永远别先写 `int cnt;` 再指望等会儿补。（栽过 5 次）
- **「每一组 / 每一次都要重新数」的变量（`cnt` / `sum` / `k` / `len`），连声明一起搬进那一层循环的花括号里面。**
  写完一个循环体，扫一眼花括号**外面**的变量，逐个问：「它的值会带到下一组去吗？」会 → 搬进去重新出生。
- **数组开多大，照抄题面上的上界再 +5**（`n ≤ 1e5` → `a[100005]`）。大数组（几十万以上）记得加 `static`，别放栈上。（栽过 2 次）
- **看到 `^` 先停一秒** —— C 里它是**按位异或**，不是乘方（`2^5-1` 算出来是 6，不是 31）。
- **范围里出现 `2^31` / `10^10` 这种「刚好卡在类型边界上」的数，先定类型再动笔。**
  `int` 最大只到 `2^31 - 1`；题目写到 `2^31`（**而不是** `2^31 - 1`）就是在暗示要用 `unsigned int` + `%u`。
  而且**答案也可能比输入更大** —— 高低位交换题里 `n = 65535` 的答案是 `4294901760`，用 `int` 存会打出 `-65536`，**编译器一个字都不警告**。
- **发现「顺序不影响答案」时，十有八九连排序都不需要。**

📄 上面这些口诀的详细版 → 见上面的「专题笔记」一节，按症状查。

## 提交前 30 秒检查清单

1. 构建窗口最后一行是不是 `0 error(s), 0 warning(s)`？（**警告也要清零**，不能只看红字）
2. 所有计数器 / 累加器都给了初值吗？
3. `scanf` 格式串和变量对得上吗？该 `&` 的都写了吗？
4. `printf` 的 `%d` 数量和参数数量对得上吗？
5. 每一行的 `\n` 都在行尾吗？
6. 题目给的**最小**和**最大**输入，你的程序会怎样？（除法、取模、数组下标是头号杀手）
7. 输出的大小写和标点，和题目要求一字不差吗？
8. **数一下输出几行** —— 和样例对得上吗？（抓 `return` / `continue` / 循环变量写错这类编译器看不见的错）
