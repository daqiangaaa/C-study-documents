每道题**都是自己先写**——跑不出来、WA 了、编译报错了，再回头找原因。AC 之后归档到 `solutions/`。

> **这里不只放对的代码。**

**为什么要分「比赛3/」和「solutions/」？**
`比赛3/main.c` 是**草稿纸**，每做一题就被覆盖；`solutions/` 是**档案柜**，进去就不动了。
分不开的结果就是——两周后想找某道题的代码，发现已经被下一题覆盖掉了。

## 编译方式

**Code::Blocks 25.03**（自带 MinGW，gcc 14.2.0）。

编译器选项设置成：

```
-finput-charset=UTF-8 -fexec-charset=GBK -Wall -O2
```

⚠️ 那个 **`-O2` 不能省**：`-Wall` 单独开着**抓不到**「变量没初始化」，加上 `-O2` 才会报
`warning: 'cnt' may be used uninitialized [-Wmaybe-uninitialized]`。

或者命令行直接编：

```bat
"C:\CodeBlocks\MinGW\bin\gcc.exe" -Wall -O2 某个文件.c -o 输出.exe
```

⚠️ **源码路径不要用中文。** MinGW 的链接器处理中文路径会直接失败：
`ld.exe: cannot open output file E:\????\_t.exe: No such file or directory`

## 一直复用的三句口诀

> **`\n` 是这一行的句号，写在行尾。**

> **信息后面还要用就存数组，用完就扔就不存。**

> **scanf 认死理，printf 不挑食。**（`double` 的 scanf 要 `%lf`，printf 用 `%f` 就行）

> **`scanf` 的返回值有三种：`1` / `EOF` / `0`。** 读到 EOF 的循环一律写 `== 1`；`!= EOF` 挡不住"格式对不上"（返回 `0`），那就是死循环。

还有一条专治死循环：**循环体里必须有东西能让「条件看的那个变量」变假。**
写循环先答两问——① 条件看的是哪个变量？② 循环体里改的是**那个变量**吗？
答不上第二个就是死循环，而**编译器一个字都不会警告**（只判断一次要用 `if`，
只有「反复做同一件事」才用 `while`）。已经栽过**四次**，四张不同的脸见 [`易错点总表.md` ⑦](易错点总表.md)。

加分项：**声明的那一刻就把初值写上**——`int cnt = 0;` 当一个整体敲，
永远别先写 `int cnt;` 再指望等会儿补。

加分项 2：**「每一组 / 每一次都要重新数」的变量（`cnt` / `sum` / `k` / `len`），连声明一起搬进那一层循环的花括号里面。**
写完一个循环体，扫一眼花括号**外面**的变量，逐个问：「它的值会带到下一组去吗？」会 → 搬进去重新出生。

加分项 3：**数组开多大，照抄题面上的上界再 +5。**（`n ≤ 1e5` → `a[100005]`）
这条已经栽过**两次**：KUN 判断题（题目 10⁶，只开了 100005）、前 m 小的数（题目 1e5，只开了 10005）。
另外大数组（几十万以上）记得加 **`static`**，别放在栈上。

加分项 4：**看到 `^` 先停一秒**——C 里它是**按位异或**，不是乘方（`2^5-1` 算出来是 6，不是 31）。
C 语言没有乘方运算符；数据范围大到 `1e9` 时，那通常是「**别算，去找公式**」的信号。

加分项 5：**范围里出现 `2^31` / `2^32` / `10^10` 这种「刚好卡在类型边界上」的数，先定类型再动笔。**
`int` 最大只到 `2^31 - 1 = 2147483647`；题目写到 `2^31`（**而不是** `2^31 - 1`）就是在暗示要用 **`unsigned int` + `%u`**。
而且**答案也可能比输入更大** —— 高低位交换题里 `n = 65535` 的答案是 `4294901760`，用 `int` 存会打出 **`-65536`**，
**编译器一个字都不会警告**（`unsigned` 和 `int` 的区别不在语法上，在「最高位算不算符号位」）。

加分项 6：**发现「顺序不影响答案」时，十有八九连排序都不需要。**
打分题要去掉一个最高分和一个最低分，两头的各一个 ⇒ 顺序白算：`sum - mx - mn` 就够了，`O(n)`、一个数组都不开；
`sort` + `greater<double>()` 那一套是把整个数组排好了才取中间，白费力气。
